# Usability pack (U1-U5) for v0 (CTO plan, 2026-10-05; PO decisions in docs/product/decisions.md 2026-10-05)
Verdict of the rethink: KEEP the code; the engine is built and heavily tested; what blocks use is: (1) the first selection pass takes 1-2 h and a restart repeats it from zero (backfill state is in memory), (2) nothing is followed until ALL candidates are done, (3) nothing is visible in Telegram (no leaders list, no progress), (4) config values differ from the PO's numbers (needs local edits), (5) the live copy path (leader fill -> gate -> paper broker -> post) has not yet been seen end to end on the PO's PC.
## U1 config alignment (money-path ceiling change: reviewer-risk required)
Defaults in config/*.toml so the PO needs NO local edits: select.max_followed = 7 (min_followed <= 7: choose 3), risk.max_leverage_alt = 10 (ceiling 1..10, tests/core/test_ceilings.py pins the range: update), risk.max_leverage_high_tier = 10, risk.max_share_risk_fraction = 0.015 (risk per trade 1.5%: inside the 0.5-2% ceiling), risk.per_trade_fraction = 0.01 (ceiling 1%), risk.daily_loss_limit = 0.05 (ceiling 5%), risk.weekly_loss_limit = 0.10 (ceiling 10%), risk.max_total_open_risk_fraction 0.10 (ceiling), clock.max_offset_uncertainty_ms = 500 (ceiling 500), scoring.candidates_k stays 50, hl.rest_weight_budget_per_min = 1100 and hl.scoring_weight_share = 0.6 (CTO: leave 40% = 440/min for exits and the trading path once positions exist; raise during the first pass is not automatic), risk.max_open_positions = 10 stays. min_liq_distance_stop_mult = 3 stays. The designer must check every dependent cross-key rule in core/config.py and keep all existing tests green or document the supersession.
## U2 selection persistence (restart must not repeat the work)
Persist to disk (under the data root, e.g. copytrade-data/cache/selection/, JSON lines or one file per wallet; atomic write; versioned; corrupt/old entries are ignored with a warning, never fatal): screen results per wallet with the cooldown end (S1-S9 outcome, until_ms), too-active/empty drops with cooldown, completed wallet inputs (fills, portfolio, clearinghouse, role, candle bars per coin) with their fetch time. On start the Backfiller/PacedInputs reloads what is still fresh by the existing stale rules (fills older than scoring.stale_input_mult x interval are refreshed incrementally from the last fill time, not refetched in full) and cooldowns stay in force. No secrets. A restart in the middle of the first pass resumes with the same done/screened counts.
## U3 follow early (reverses F6.AC4)
Scoring and following start as soon as >= 12 candidates are complete (CTO constant, documented, no new config key unless the designer shows it is needed: ESCALATE); each cycle re-scores all complete wallets and re-ranks; followed set max select.max_followed (7), min select.min_followed; as more candidates complete they can enter by the existing hysteresis (join/drop rank, confirm cycles, min follow hours, swap margin). Status stays 'backfilling' in the progress line but followed > 0 is allowed; the screen/backfill keeps running in the background with the existing budget split; followed-wallet refreshes keep priority over new screens (R3-SD5 advisory becomes a requirement here: interleave at least one followed-wallet refresh per N screens).
## U4 Telegram visibility
Commands: /leaders (the followed wallets: short address, rank, score, follow start, open copies count, pause state), /progress (pass state: candidates done/total, screened, screen_ok, rejected, cooling, followed count, time since start, ETA estimate or 'unknown'), and automatic messages: 'selection pass complete', 'leader followed <addr> rank r', 'leader dropped <addr> reason', 'no eligible leaders', once per event (no spam; the existing alert queue/throttle). Authorised chat only, no PIN (read-only). Keep existing commands unchanged. No secrets/PIN in any message.
## U5 first live copies and latency (PO smoke test, not code)
After U1-U4: the PO runs the bot; the CTO checks the first copied trade end to end (post in Telegram, stop placed, adds/reductions, close, restart with an open position) and measures leader-fill -> our order lag (target median <= 5 s, p95 reported).
## Out of scope

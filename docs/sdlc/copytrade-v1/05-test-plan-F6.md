## Pinned decisions (defaults stand until the PO/PM says otherwise)
1. The hysteresis policy is a pure function `apply_cycle(cfg, state, result, *, now_ms, paused)` over F5's `CycleResult`; it reads `rank` and `score` and never recomputes them.
2. Join streak: consecutive cycles eligible, not paused, rank <= join_rank (missing, ineligible or rank above resets). Join when streak >= confirm and followed < max. Drop streak: consecutive cycles ineligible/missing/rank > drop_rank; the drop needs streak >= confirm AND followed >= min_follow_hours, and the streak keeps counting while protected.
3. Swap: weakest = lowest score (no score is lowest); the weakest itself must be >= min_follow_hours old, else no swap (an older, stronger wallet is never swapped instead); margin inclusive; best-ranked candidate first; drops and joins before swaps.
4. Safety triggers in a cycle: any blow-up flag, `G15` among reasons, or the copy pause. Immediate, no streak, no minimum follow time.
5. Copy drawdown = peak-to-trough of the wallet's cumulative copy P&L (peak starts at 0), compared with `max_copy_dd x leader_allocation_fraction x equity` using the equity passed in that call, `>=`. Losses are pnl < 0; a profit resets the run; pnl 0 neither counts nor resets (untested). The pause lasts for the life of the process.
6. Refusal reasons: `leader_paused` (safety-dropped or paused), then `no_eligible_leaders` (last cycle had 0 eligible), then `not_followed` (the spec names none for a wallet we do not follow; new constant). Only OPEN and ADD are refused.
7. Slots are checked by the manager, which knows which dropped wallets still have shares (policy does not); a deferred join keeps its streak. Ledger kinds: `select_cycle` (t_ms, status, eligible_count, followed, decisions), `follow_deferred` (wallet, reason, t_ms), `cycle_overrun` (started_ms, finished_ms). A dropped wallet with no open share is released in the same call, one with shares at the first `tick()` after the last share closes.
8. A wallet whose `clearinghouseState` cannot be fetched is not joined this cycle (no detector or feed call); it is retried next cycle.
9. Candidates = the first `scoring.candidates_k` leaderboard rows in the order served; followed and held wallets are always also scored. The backfill gate is latched (set after the first complete pass) and lives in `run_cycle`, not in `apply_cycle`.
10. During a leaderboard outage only followed wallets are refreshed and scored; no joins, swaps or rank drops happen.
11. Cadence is anchored to the start of the previous cycle. Cycle duration is measured on the injected clock from start to the end of scoring; `> max_cycle_duration_min` is an overrun (the scoring result is still persisted by F5's store; the followed set and the policy state are untouched).
12. The real `Backfiller` uses the F3 REST client at SCORING priority (the client paces itself); candles go through F4's `CandleSource`; `funding` stays empty (the REST client has no `userFunding`).

## Spec issues and decisions needed
- **G15 and missing data.** F5 fails G15 whenever the current drawdown cannot be computed (no data at all), and F6.AC2 makes any G15 failure an immediate safety drop. A wallet with no usable inputs is therefore dropped at once, skipping hysteresis and the 24 h minimum. Fail-closed, but PO/PM should confirm this is intended (the tests use "stale but computable" inputs for the zero-eligible cases).
- **Refusal reason** for a rank-dropped or never-followed wallet is not in the spec (`not_followed` chosen).
- **Copy drawdown** definition, the pause duration (forever) and pnl == 0 handling are not in the spec.
- **State is in memory only.** Restart reconstruction of the followed set and of the pause is F13 (on hold); after a restart the detector rebuilds follow state from the ledger but the manager starts empty.
- **Safety drop during an outage**: pinned as "still allowed"; only the copy-pause path is tested (it needs no leaderboard).
- **No concrete adapters** (leaderboard fetch, state source over `HlRestClient`, open-share source from F12, F5 `ScoreStore` over the ledger, costs) are in F6; F12/F21 wire them.
- `Fill` fixtures are still synthetic (F3 README): replace with recordings before /verify.

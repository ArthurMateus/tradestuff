### Pinned design of the reload (developer may add helpers; names below are recommendations, not tested directly)
- Broker state is **replayed from the ledger** (`paper_order`, `fill`, `trade`, `paper_stop`, `paper_cancel`, `paper_stop_trigger`, `paper_reject`, `partial_fill`, `paper_funding`): the ledger is the source of truth (A7), so a crash between a fill and the next checkpoint cannot lose a position. Recommended: `copytrade/paper/restore.py` (pure replay to a `BrokerSnapshot`) and `PaperBroker.restore(snapshot, *, now_ms)`: **sets broker time first**, installs positions/shares/cash, re-registers stops and re-queues pending exits under **new** client order ids (`<old>:r<n>`-style, deterministic, written to the ledger as `paper_stop`/`paper_order` records so the next restart sees them), drops pending entries with a `paper_cancel` record (reason `restart`).
- Manager, share book, `_tracks`, `_tids_done`, `_handled`, `_leader_pos`, `_ours_won`, `_flip_wait`, `_missed_*`, `_audit_end`, `_stretches`, `_entry_orders`, `stop_seq`, synthetic tids, gate `_known_entries` and the order-rate window come from the latest `runner_checkpoint` ledger record (written while running when state changed, and at `stop()`), plus the ledger records after it. Recommended: `PositionManager.export_state()/restore_state()`, `PositionBook.restore()`, `RiskGate.restore(...)`, `FollowManager.restore(followed, subscribed)` (followed from the last `select_cycle`, `followed_at_ms` from `follow_started`, a wallet with a later `leader_paused` record is NOT followed, a dropped wallet with an open share stays subscribed). All reviewed by reviewer-risk.
- Anything the two sources disagree on, or cannot prove, is an `Uncertainty`: alert `startup_uncertain` (text names the code), `RiskGate.pause()` (persisted manual pause: refuses entries as `paused`), `StartReport.entries_blocked`. The PO acknowledges with the existing Telegram `/resume`. Positions, stops and exits are never dropped or blocked because of an uncertainty.

## 3. Pinned ambiguities (designer default; PO or architect may overrule)

1. **Reload source of truth**: broker by ledger replay, manager/book/follow by the latest `runner_checkpoint` record (section 1). Checkpoint cadence: every iteration that changed state (throttled to once per second of local time) and at stop.
2. **"Refuse new entries until the PO acknowledges"** = the existing persisted manual pause (`gate.pause()`), acknowledged by the existing Telegram `/resume` (no PIN, PO decision already recorded). A clean stop never sets the pause.
3. **Pending entries at a restart are dropped** (ledger `paper_cancel`, reason `restart`), not re-queued: an entry decided before a crash is stale by definition (F10 `stale_decision`). Pending **exits** are re-queued under new client order ids.
4. **Exchange clock** (HL has no server-time call): `ExchangeOffsetSource` reads the exchange timestamp of one `l2Book` response and brackets it with the local clock (uncertainty = half the round trip + 1 ms). The PO should confirm this is acceptable against `clock.max_offset_uncertainty_ms = 100`; with a slow link the entries are refused as `clock_unsynced` (fail closed).
5. **Jump guard**: a target more than `elapsed local + 2 x clock.max_offset_uncertainty_ms` ahead of the last accepted target is not advanced; alert `clock_jump` once per episode; a persistent jump is accepted once local time has caught up with it (or after a restart). Entries meanwhile are refused by the gate itself (`bad_decision_time`).
6. **Stall heartbeat** threshold = 3 x `ledger.heartbeat_interval_s` of local time with no completed `step()`, raised by the `r0-watchdog` thread, once per episode.
7. **Flatten re-run**: every `FLATTEN_RERUN_INTERVAL_S` (5 s) with a new run id while the last report has `in_flight` or `still_open`, at most `FLATTEN_RERUN_MAX` (12) times, then alert `flatten_incomplete`. The bot is given a thin runner-owned flatten supervisor in place of the manager. **The limit/alert path is not covered by a test** (no reproducible persistent `still_open` on the real stack); reviewer-risk and QA must check it.
8. **Missing Telegram token = refuse to start** (a runner that cannot alert is flying blind). Missing PIN hash/salt = starts, `/flatten` refused (F14 fail-closed).
9. **Retention**: days strictly older than `storage.local_retention_days` (T-7 kept, T-8 pruned for 7), closed files only, ledger record first. Reading a pruned file through `RecordingReader` is a known consequence (the ledger still lists it): replay/evaluation are not in R0.
10. **Disk start requirement** = `recording.disk_floor_free_gb + recording.disk_resume_margin_gb` over the three storage volumes (the recorder could not resume below it); alert level = `recording.disk_alert_free_gb`.
11. **Stop**: Ctrl+C / SIGTERM / SIGBREAK and Telegram `/pause` (no entries) / `/flatten`; there is NO `copytrade stop` subcommand (no IPC in v0). A system failure (ledger/broker failure) re-raises after a best-effort clean stop and exits 1.
12. **Entry policy** vetoes also on the runner's own refusals (F6 not followed / paused / no eligible, F3 stale feed, F4 disk floor, access degraded, stopping). Adds (ADD) are covered by the gate only (clock, pause, limits); a stale feed or disk-floor refusal of an ADD is NOT enforced (open item for the PO).
13. **Universe** for books and recording = F4's rule (coins traded by followed or top-K wallets over `recording.universe_lookback_days`, via `userFillsByTime`) plus coins of open shares and pending entries; HIP-3 is empty in v0.
14. **ScoreStore** = in-memory plus one summary ledger record per cycle; **CostModel** = config fallbacks only (`ConfigCostModel`); **ReturnsSource** from stored hourly candles, `None` when unknown (the gate then fails closed).
15. Run id = `r<start exchange ms>`; recorded in `runner_start`.

## 6. What the suites prove and what they deliberately do not

- **Prove**: the wiring with real components over real sockets; the contracts listed in the R0 sections of W0/F10/F11/F12/F14; restart behaviour from clean stops and from the on-disk state of a hard kill (snapshot of the ledger and state directories at the kill instant); fail-closed startup refusals; secrets absent from every sink; exits and stops never blocked by uncertainty, disk floor or stop.
- **Do not prove (later gate)**: real TLS to `api.telegram.org` and Hyperliquid, real `websockets` behaviour on Windows, the real `shutil.disk_usage` on the PO's volume (QA, `/qa` with a throwaway bot and the PO's PC); a real kill -9 with a half-written ledger line (F2 covers the torn tail; QA); the 24 h dry run, zero `bad_timestamp` over a day, p95 latency (v0 evidence gate, simulation); scoring/selection quality with real data (the fake leaderboard is below the 1,000-row minimum so F6 holds the seeded follows: F5/F6 own that); the flatten re-run limit alert (section 3, item 7); concurrency under load (the dedicated-thread and shared-lock tests are behavioural, not a proof of freedom from races: reviewer-risk reads the lock discipline); replay/evaluation/LLM/calendar/archive (not in R0). Fixture payloads for `meta`, `metaAndAssetCtxs`, `fundingHistory` and the WebSocket `l2Book`/`allMids` frames are written from the public documentation, not recorded: replace with `hl_sample.py` recordings before /verify (EXPLORE REQUEST for the PO's hl_sample run).
- Money-path mutation testing (cosmic-ray on `runner/`) is a reviewer-risk/QA item; the tests were written so that the main mutants die: skipping the broker-time set before restore, reusing old client order ids, not rebuilding the rate window, advancing before/after marks, dropping the lock, accepting a jump, resuming a paused state, skipping the disk check, deleting before ledgering.

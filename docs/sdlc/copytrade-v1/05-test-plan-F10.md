Epic copytrade-v1, branch `feat/copytrade-v1/F10-risk`. Money-path feature. Spec: `04-spec.md` F10.AC1-AC10 with Amendments 1-11, §3.6 risk keys, §5, §10 ownership (`src/copytrade/risk/**`). ## Run summary

- 309 new test cases in `tests/risk/` (10 files). Hypothesis: 11 property tests, including the AC10 main property at 10,000 generated cases.
- Against the interface stubs: **307 fail, 2 pass**. Failure reasons: 306 x `NotImplementedError` from a stub, 1 x `AssertionError` (the static chokepoint scan finds no `.submit(`/`.place_stop(`/`.issue(` call in `risk/gate.py` yet). 0 import, collection or fixture errors.
- The 2 passing tests are static guards that are correct on stubs by design: no float literal or `float()` in `src/copytrade/risk/**`, and the settings carry no calendar/blackout key. They must keep passing.
- The rest of the suite is unaffected (F1.AC3/AC4 static scans cover the new package and hold). ruff check, ruff format --check and mypy (strict) are clean.
- **Validity probe (not committed, scratch copy deleted).** The expected values are hand-computed, so I wrote a throwaway reference implementation and ran the suite against it: 308/309 pass (the one failure is the reference missing a `ConfigError` for an absent `risk.high_leverage_coins`, which the test correctly demands). 17 hand mutants of it (drawdown `>=` to `>`, daily and weekly `<=` to `<`, leader cap removed, symbol cap removed, per-share cap removed, bucket direction filter removed, notional cap ignoring the existing position, AV age `>` to `>=`, rate limit `>=` to `>`, rate window `>` to `>=`, stop-widening `<` to `<=`, liquidation `>=` to `>`, min order `<` to `<=`, ceiling ignoring the exchange max, exit qty check removed, `advance_to` removed) were each killed. The developer must not treat the reference as a design.

What is real and what is faked. Real: `RiskGate`, `PaperBroker`, `GateAuthority` (a recording subclass `SpyAuthority` that calls the real `issue`), the F2 `Ledger`, the F11 `liquidation_price`. Faked, because they are true boundaries or not built yet: exchange-time clock, book/meta/funding sources (F11's own fakes), `AccountView` and `ShareBook` (F12, not built), `ReturnsSource` (F4 candles), `EntryCalendar` (F8, not built). No network, no sleeps, no floats. Ledger write failure is induced by patching `os.fsync` (filesystem boundary), as the F2 tests do.

Conventions the tests fix (written into the stub docstrings): the audit record is ledger kind `risk_decision` with keys `signal_id, approved, reason, client_order_id, leverage, leverage_ceiling, posted_margin_usd, liquidation_px, mirror_notional_usd, risk_notional_usd, final_notional_usd, qty, checks[{check,passed,detail}]`; the drawdown event is ledger kind `risk_halt` with `reason == "drawdown"` plus alert kind `drawdown_pause`; refusal reason codes are listed in the `RiskGate` docstring; open risk of a share is supplied by F12 in `ShareExposure.open_risk_usd`.

## Spec issues and decisions needed (details in the report to the CTO)

1. **F11 keeps the FIRST entry's leverage on an add** (`broker.py`: "the leverage stays the first entry's"), but F10.AC4 chooses L afresh at every add. The gate can approve an add at a lower L than the position really carries, so the margin it checked is not the margin the broker holds. Pinned as the spec says; needs a ruling.
2. Pinned defaults the spec does not state (flagged in the tests): unknown returns for a coin put it IN the bucket; order rate window is (now - 60 s, now] and counts every order sent; unknown equity is `equity <= 0` too; the opening equity of a day/week is the first mark at or after 00:00 UTC (the tests pass under either reading, by construction); daily/weekly halts expire by time, not by a mark.
3. `client_order_id` exact encoding and truncation ("as the broker requires") are not specified; the broker has no length rule. Pinned: lowercase hex, 32-64 chars, unambiguous, order-insensitive tids, `action` = `ActionKind.value`.
4. Drawdown `/resume` semantics (does the peak reset?) are unspecified and untested.
5. "An unverified ledger" is pinned as `Ledger.failed` (A2/F2.AC6); a full chain verify per entry would be expensive.

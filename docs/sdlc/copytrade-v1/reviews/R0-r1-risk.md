RISK-53 [developer+designer] timebase.py:44-51 JUMP GUARD CAN FREEZE BROKER TIME FOR GOOD: elapsed comes from the wall clock and exchange_now = local + offset; once the offset estimate rises by more than 200 ms (one laggy l2Book sample then a normal one) or Windows steps the wall clock back by more than 200 ms, every later sample is refused (probe: 7,200/7,200 iterations skipped over an hour; price 5 below the stop for 2 min and the stop never triggered; /flatten returned an empty report, position still open 60 s later; one `clock_jump` alert, no reminder; the watchdog stays silent because iterations still complete). A forward wall-clock step is accepted as is (broker time 5 s ahead). The pinned test `test_R0_AC4_a_sustained_jump_is_accepted_once_local_time_has_caught_up_with_it` models an exchange clock that does not follow local time, which is wrong. Fix: measure elapsed with a MONOTONIC clock; rebase when a new offset is consistent over N samples or a fresh estimate (alert on rebase); never freeze exits indefinitely; re-alert while frozen with positions open. Designer: rewrite the time-base tests (exchange time = local + offset; offset step; backward wall step) and assert stops still trigger within a bounded time.
RISK-54 [developer+designer] paper/broker.py:414 (cancel written BEFORE `paper_stop` at 418-430), :450 (same for exits); runner/reload.py:229-256; positions/manager.py:974-1010: A TORN RESTORE REMOVES THE STOP-LOSS FOR GOOD. `_restore_stop` cancels the old id before it writes the new stop; a kill -9 in between (console closed, Windows Update reboot) means the next replay has no SL; `restore_state` keeps `sl_cid` = the old id (not in `cid_map`), `_replace_stop` sees sl_qty == qty and never re-places; reload only raises the generic `checkpoint_behind_ledger`; nothing at reload checks each OPEN share against `PaperBroker.stops()`. Probe: after restart only the TP existed; price 5 below the old SL, position stayed open. Fix: write the new stop/exit record FIRST, then the cancel; at reload check every OPEN share against `broker.stops()` (one SL on the opposite side for the share's qty); take `sl_cid` from the broker's restored stops by share_id, not the checkpoint; if the SL is missing re-place it through the gate or flag it and close the share (also closes F12 RISK-35). Designer: a torn-restore test that truncates the ledger right after the restart `paper_cancel` and asserts the share has a live SL.
RISK-55 [developer+designer] runner/runner.py:551-563, :361-368; app.py:60-62: THE RUNNER DIES SILENTLY WITH OPEN POSITIONS. Any exception escaping `step` ends the run (`run()` calls stop() and re-raises): e.g. a LedgerWriteError from one transient fsync PermissionError (antivirus lock), any error other than OSError/HlError in feed/recorder/follow. No Telegram alert, the watchdog dies with the process, nothing restarts the bot (probe: PermissionError -> LedgerWriteError, zero Telegram messages, position still open at exit). Positions are unmanaged from then on (the broker only moves on advance_to/on_mark). Fix: in `run()` on any exception queue a critical `runner_stopped` alert naming the open positions and flush it on a path that does not depend on the failed ledger; document a supervised restart (Windows Task Scheduler, restart on failure) in the README. Designer: inject an fsync failure and assert the alert arrives.
RISK-56 [developer+ARCHITECT, touches the F11 contract "do not advance while unsynced"] runner.py:308-318; timebase.py:63-71; hl/rest.py:79-90 (one connection per request); config/platform.toml:10-12: AN UNSYNCED CLOCK STOPS ALL POSITION MANAGEMENT. One l2Book round trip over ~198 ms leaves the clock unsynced for 10 min (offset_interval_s=600); probe: one 260 ms round trip, then 120/120 iterations skipped with the price 5 below the SL. Fix: an unsynced clock should refuse ENTRIES only; keep advancing for exits, stops and liquidations from a degraded MONOTONIC projection (last accepted target + monotonic elapsed; the gate already stamps exits that way); re-estimate sooner while unsynced; leave TCP/TLS handshake time out of the measured round trip or use a persistent connection; measure at /qa.
RISK-57 [developer+designer] runner.py:330-334, :324-327; adapters.py:166-185 (MarketHub only logs `market_ws_down`): NO ALERT WHEN MARKS STOP ARRIVING (R0 contract RISK-23 not met, "alert after N rejected marks").
